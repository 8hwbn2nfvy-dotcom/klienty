# Правила проекта «Клиенты»

Владелец работает с iPad. Описание проекта и инструкции — в README.md.

## Общие правила
1. Перед кодом задавать вопросы по всему, что не решено.
2. Результат — файлы в репозитории, не артефакт и не страница-план.
3. Коммиты сразу в `main`, без веток.
4. Ошибки и откаты показывать на странице. Не ставить молча «готово»; если действие ничего не изменило, так и написать.
5. Не перерисовывать страницу по таймеру.
6. Во внешних API — User-Agent с названием проекта и контактом (`app/config.py`).
7. В CSS есть `[hidden] { display: none !important; }`; телефонная версия не уезжает за край экрана.
8. База с миграциями (`migrations/NNN_*.sql`, старые файлы не править).
9. Не проверенное из-за сети — пометить 🟡 и попросить владельца проверить на живом сайте.
10. Сделанное или решённое без прямого указания — перечислить отдельно в конце.
11. Настройку сервисов объяснять простыми словами, с прямыми ссылками и точным названием кнопки; каждую пару «имя переменной → значение» — отдельным блоком для копирования.

## Инструменты и подключения
- Если в сессии подключены коннекторы Render и Supabase, использовать их самому, не дожидаясь просьбы:
  - деплой и статус сборки на Render;
  - логи сервиса на Render, когда что-то падает;
  - проверка таблиц и миграций в Supabase.
- Если коннектора нет, не угадывать состояние. Дать владельцу прямую ссылку на нужную страницу (Render: страница сервиса, вкладка Logs; Supabase: страница проекта, раздел Table Editor) и точное название того, что там смотреть.
- Перед словом «готово» проверить живой адрес (`/api/health` и главную страницу) и написать результат. Если проверить не удалось — 🟡.
- Коннекторы не меняют правил выше: `main` без веток, ошибки на странице, всё неясное — вопросом владельцу.
